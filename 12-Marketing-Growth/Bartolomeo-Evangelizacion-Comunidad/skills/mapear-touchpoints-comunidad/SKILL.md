# Mapear touchpoints de comunidad

## Propósito

Producir un mapa verificable de dónde la audiencia descubre, habla, aprende y defiende el producto — y dónde abandona — para priorizar sistemas comunitarios (no tácticas sueltas).

## Entradas

- Producto o iniciativa y audiencia objetivo.
- Canales conocidos (Discord, Slack, GitHub, foros, redes, eventos, soporte, newsletter).
- Restricciones de jurisdicción/compliance si aplican.
- Datos o muestras de actividad (o declaración de que faltan).
- Objetivo de Morgans (descubrimiento, auditoría, priorización).

## Procedimiento

1. Lista todos los touchpoints relevantes (propios y where-they-talk).
2. Para cada touchpoint anota: dueño, propósito, tamaño/actividad observada, normas, riesgos.
3. Reconstruye un journey típico: descubrimiento → primer valor → pertenencia → contribución → advocacy.
4. Marca el mayor drop-off con evidencia o supuesto explícito.
5. Separa canales “anuncio” de canales “conversación peer”; flaggea los que son solo broadcast.
6. Prioriza 1–3 intervenciones de mayor apalancamiento (foundation antes que escala).
7. Identifica handoffs a Carrot (activación), Vivi (docs) o Shakky (posicionamiento) si el drop-off no es comunitario.

## Salida

```md
# Mapa de touchpoints — [producto/audiencia]

## Touchpoints
| Canal | Dueño | Propósito | Actividad observada | Normas | Riesgo |
|---|---|---|---|---|---|

## Journey
1. Descubrimiento: …
2. Primer valor: …
3. Pertenencia: …
4. Contribución: …
5. Advocacy: …

## Drop-off principal
- Dónde: …
- Evidencia/supuesto: …
- Apalancamiento propuesto: …

## Prioridades (máx. 3)
1. …
2. …
3. …

## Handoffs
- …

## Supuestos y pendientes
- …
```

## Casos límite

- Sin datos de actividad: mapa cualitativo + preguntas de instrumentación; no inventes MAU.
- Comunidad financiera regulada: marca canales donde no se puede dar consejo de inversión.
- Multi-producto: un mapa por audiencia primaria; evita monolitos confusos.
- Canal tóxico dominante: prioriza normas/moderación antes que growth.

## Validación

- Cada touchpoint tiene dueño o “sin dueño” explícito.
- El journey distingue pertenencia de vanity de awareness.
- El drop-off principal está justificado.
- No se recomienda programa de embajadores si falta canal fiable.

## Criterios de terminado

- Artefacto de mapa entregado.
- Prioridades ≤3 con racional.
- Riesgos y supuestos listados.
- Listo para rituales/embajadores o handoff claro.
