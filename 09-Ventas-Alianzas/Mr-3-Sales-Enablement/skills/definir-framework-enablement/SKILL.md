# Definir framework de enablement

## Propósito

Construir el molde operativo que decide qué necesita un rep en cada etapa, dónde vive, quién coachea y cómo se verifica el uso — distinto de una estrategia puntual o de un playbook suelto.

## Entradas

- Objetivo (ramp, win-rate, consistencia de mensaje).
- Tamaño del equipo y etapa (early / growth / enterprise).
- Motion (sales-led / product-led / híbrido).
- Metodología e ICP vigentes (si existen).
- Inventario mínimo de contenido y herramientas.

## Procedimiento

1. Declara el objetivo medible del ciclo (no “mejorar enablement”).
2. Fija o propone foundation: metodología, ICP, messaging core.
3. Diseña las 4 capas: foundation → contenido → coaching → verificación.
4. Ajusta profundidad al tamaño del equipo (lightweight vs certificación formal).
5. Produce mapa base etapa→contenido→checkpoint→métrica.
6. Lista gaps y dueños (Buggy, managers, Crocodile, Bon Clay, Vivi).
7. Define el primer ciclo de verificación (muestreo de deals) antes de “done”.
8. Separa explícitamente framework vs estrategia vs maturity assessment.

## Salida

```md
## Objetivo del ciclo
## Foundation (metodología / ICP / messaging)
## Capas del framework
## Mapa etapa → contenido → coaching → métrica
## Ajuste por etapa/motion
## Gaps y dueños
## Primer ciclo de verificación
## Riesgos / pendientes
```

## Casos límite

- Equipo <15 reps → framework liviano; no fuerces certificación enterprise.
- Sin metodología acordada → no construyas battlecards; escala foundation a Buggy.
- Solo piden herramienta/LMS → exige framework antes de seleccionar tool.

## Validación

- Las 4 capas están presentes o gaps etiquetados.
- Mapa etapa→métrica existe.
- Verificación no está omitida.
- No se inventan métricas de ROI.

## Criterios de terminado

- Buggy puede operar el ciclo con el mapa y el plan de verificación.
- Queda claro qué es framework vs playbook vs strategy.

## Casos de evaluación

| Caso | Entrada | Resultado esperado |
|---|---|---|
| Normal | Growth sales-led, MEDDIC parcial | Framework 4 capas + mapa + verificación |
| Ambiguo | “Necesitamos enablement” | Preguntas de objetivo/motion + borrador de capas |
| Límite | 8 reps early-stage | Framework liviano sin certificación pesada |
